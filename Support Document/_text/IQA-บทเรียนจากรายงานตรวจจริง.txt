## Tier A — รายงานระดับ Lead Auditor (ต้นแบบ)

### 1. ลูกหีบ (ไฟล์ตัวอย่าง) — Gold Standard
- **โครงสร้าง NC ดีเยี่ยม:** ทุก NC เขียนแบบ **Requirement → Evidence → Gap** เช่น ข้อ 25 (สอบเทียบ MM-07 เกินกำหนด), ข้อ 63 (จารบีไม่ใช่ Food Grade NSF H1), ข้อ 53/54 (พื้นแตก/น้ำขัง ระบุเวลา 11:00 น.)
- **C มีหลักฐานจับต้องได้:** รหัสเอกสาร (Rev.) + วันที่ + การสังเกตหน้างานพร้อมเวลา
- **B ถูกต้อง:** ข้อ 4, 11, 14, 20, 28, 45, 57, 69 เป็น "สอดคล้องแล้วแต่ปรับปรุงได้" จริง (เช่น ข้อ 28 Competency Matrix มีแต่ยังไม่แยกทักษะ Food Safety)
- **Awareness ถูกหลัก:** ข้อ 9, 30 สัมภาษณ์พนักงาน 3 คน ตอบไม่ได้ → NC (ตรงตรรกะ awareness_competence_logic)
- **ทุก verdict = MATCH**

### 2. หม้อไอน้ำ — Gold + CAR ครบ
- จุดเด่นพิเศษ: NC ข้อ 18, 27, 46 เขียน **Correction + Root Cause + CAP** ครบในช่อง Finding (เกินมาตรฐานทั่วไป)
- ข้อ 18 (Flow Meter เกินกำหนดสอบเทียบ 53 วัน) — หลักฐานเชิงปริมาณ + ตรวจ Log ย้อนหลังยืนยัน → NC สมบูรณ์แบบ
- B ข้อ 47 ถูกต้อง (มี Trend Graph อยู่แล้ว เสนอต่อยอด SCADA)

### 3. บรรจุ — ครบ ทุกมิติ
- NC มี Sampling เชิงปริมาณ: ข้อ 18 (MOC 4/9 ครั้ง=44%), ข้อ 26 (3 คนไม่มีแบบประเมิน), ข้อ 50 (Metal Detector 6/30 กะ=20%), ข้อ 81 (ATP 4/12=33%)
- B = Best Practice: ข้อ 10, 28, 57 (ความตระหนักสูงกว่าเกณฑ์/ปรับผัง U-shape)

### 4. บริหาร[ผู้ปฏิบัติงาน], หม้อต้ม, หม้อปั่น, Top Management
- หลักฐานอ้างรหัสเอกสาร + cross-verify หลายแหล่ง
- หม้อต้ม/หม้อปั่นมีจุดเด่น: NC แบบ "linked findings" (ข้อ 11→7, 32→4) อ้างถึงข้อบกพร่องที่เชื่อมโยงกัน ถูกหลัก ISO 19011 A.18.4

## Tier B — ใช้ได้แต่ต้องปรับ (ปัญหา under-grading)

### เครื่องมือควบคุม ([ผู้ปฏิบัติงาน])
NC ที่เขียนดี: ข้อ 6, 11, 19, 23, 35, 40 (มีหลักฐาน+อ้าง clause) ✓

**แต่พบ MISMATCH/REVIEW — ติ๊ก C ทั้งที่ Finding บรรยายการเบี่ยงเบน:**
| ข้อ | Finding บอกว่า | ติ๊ก | ควรเป็น |
|-----|----------------|------|---------|
| 16 | "มีการควบคุมแต่**ไม่มีบันทึกยืนยัน**ว่าอยู่ในเกณฑ์ตลอดเวลา" | C | NC/B (ไม่มีบันทึก = พิสูจน์ไม่ได้) |
| 17 | "ใบรับรองบางรายการ**เก่าเกิน 1 ปี**" | C | NC (เครื่องมือเลยรอบสอบเทียบ) |
| 27 | "สำเนาหน้างาน**ไม่มีตราประทับควบคุม**" | C | NC (Document Control) |
| 29 | "ปฏิบัติแต่**บันทึกไม่ครบ**ทุกครั้ง" | C | B |

→ [ผู้ปฏิบัติงาน] NC ดี แต่ **ลังเลที่จะยก NC/B** เมื่อเจอ gap เล็กๆ ทำให้ปล่อยผ่านเป็น C

### วิเคราะห์[ผู้ปฏิบัติงาน] ([ผู้ปฏิบัติงาน])
- NC ดี: ข้อ 2, 6, 11, 17, 23, 25, 32, 36, 43, 47, 51, 62, 66, 75, 79, 82, 86 ✓ (อ้าง clause ครบ)
- under-grading คล้ายกัน: ข้อ 45 ("บางช่วงข้อมูลไม่ครบทุกชั่วโมง"→C), ข้อ 60 ("บางรายการข้อมูลไม่ครบ"→C), ข้อ 22 ("เครื่องชั่งสำรองไม่พบบันทึกสอบเทียบ"→C ควร NC), ข้อ 72 ("Supplier รายย่อยไม่มี COA"→C ควร B/NC)

**คำแนะนำ Tier B:** ฝึกกฎ "ถ้า Finding มีคำว่า *ไม่มีบันทึก / ไม่ครบ / เกินกำหนด / ไม่เป็นปัจจุบัน* → ห้ามติ๊ก C"

## Tier C — ต้องปรับปรุงเร่งด่วน (ไม่ผ่านมาตรฐาน ISO 19011)

### คลังสินค้า ([ผู้ปฏิบัติงาน] ฝึกงาน) — ตัดสินจากความรู้สึก
- **ไม่มีลายเซ็นผู้ตรวจ/ผู้รับตรวจ** (เอกสารใช้ไม่ได้ตามระบบ)
- ใช้การเดา: ข้อ 2 "น่าจะมี FIFO อยู่แล้ว**มั้ง**"→C, ข้อ 4 "คิดเอาเอง"→C, ข้อ 27 "น่าจะมี เป็นเรื่องปกติ"→C → ทั้งหมด **INSUFFICIENT_EVIDENCE** (คาดเดา ≠ หลักฐาน ตาม ISO 19011 หลักการ f)
- **NC ผิดประเภท:** ข้อ 16, 17, 50 ติ๊ก NC เพราะ "**ลืมถาม/ข้ามไป**" — นี่คือความล้มเหลวของ[ผู้ปฏิบัติงาน] ไม่ใช่ข้อบกพร่องของผู้รับตรวจ → ห้ามเป็น NC
- จุดที่พอใช้: ข้อ 58 (เห็นฝุ่นเกาะ→NC), ข้อ 64 (ไม่มีรายงาน Pest→NC) มีการสังเกตจริงบ้าง แต่ remark ("คนดีอยู่แล้ว", "เชื่อใจ") ไม่เป็นมืออาชีพ

### จัดซื้อ + พัสดุ ([ผู้ปฏิบัติงาน]) — ข้อความสำเร็จรูปซ้ำ
- **Finding ซ้ำคำเดิมทุกข้อ** สลับไปมา: "ไม่ค่อยเป็นระบบ ควรปรับปรุง", "ดูแล้วหละหลวม", "ปกติดี", "เช็คแล้วผ่าน" — ไม่อ้างถึงเอกสาร/หลักฐาน/คำถามเฉพาะข้อเลย → **RESTATES/EMPTY ทุกข้อ**
- remark "ให้ไปแก้เอง / หัวหน้าแผนกต้องดูแล" = สั่ง ไม่ใช่ระบุข้อกำหนด
- NC ทุกข้อ = INSUFFICIENT (ไม่มี evidence/clause), C ทุกข้อ = INSUFFICIENT (แค่ "ผ่าน")
- เป็นการตรวจแบบ "ติ๊กให้จบ" ไม่ได้ตรวจจริง

### หม้อเคี่ยว (ผู้ตรวจ) — แย่ที่สุด + ผิดจรรยาบรรณ
- Finding ใช้อารมณ์/ดูถูก: "หย่อนยานมาก ใช้ไม่ได้เลย", "พนักงานก็ไม่รู้เรื่อง ดูไม่จริงจัง", "แทบไม่มีระบบอะไรเลย แย่"
- remark กล่าวโทษบุคคล: "พนักงานไม่ใส่ใจงาน", "หัวหน้าแผนกต้องรับผิดชอบ", "ให้ไปแก้เอง"
- **ละเมิดหลักการ ISO 19011:** Fair presentation (เกินจริง/ใส่อารมณ์), Evidence-based (ไม่มีหลักฐาน), Integrity (ตัดสินคน ไม่ใช่ระบบ)
- C ก็แค่ "ผ่าน / ปกติ / โอเคดี" คำเดียว — INSUFFICIENT
- NC ทุกข้อต้องตีกลับ: ไม่มี objective evidence แม้แต่ข้อเดียว

## รูปแบบ (Pattern) ที่สกัดได้ เพื่อเทรน AI ต่อ

### ✅ Pattern ของรายงานที่ดี (จาก Tier A)
1. **NC = Requirement + Evidence + Gap** พร้อมอ้าง Clause และระบุ Sampling (x/n = %)
2. **C = รหัสเอกสาร + Rev + วันที่ + cross-verify** (สัมภาษณ์+เอกสาร+สังเกต)
3. **B = ยืนยัน C ก่อน แล้วเสนอ improvement** ที่เฉพาะเจาะจง
4. **Awareness** = สัมภาษณ์กี่คน/ตำแหน่ง + สาระคำตอบ → อธิบายได้=C / ตอบไม่ได้=NC
5. **CAR เต็มรูป** (Correction/Root Cause/CAP) = ระดับสูงสุด

### ❌ Anti-Pattern ที่ AI ต้องจับ (จาก Tier B & C) — ของใหม่ที่เพิ่มเข้าสมอง
1. **Hedge-and-pass (under-grading):** Finding มี "ไม่มีบันทึก/ไม่ครบ/เกินกำหนด/ไม่เป็นปัจจุบัน" แต่ติ๊ก C → ต้องเตือน
2. **Guess-as-evidence:** "น่าจะ/คิดเอาเอง/มั้ง/เชื่อว่ามี" = ไม่ใช่หลักฐาน → INSUFFICIENT
3. **Auditor-failure-as-NC:** "ลืมถาม/ข้ามไป/ไม่ได้ตรวจ" แล้วติ๊ก NC → ผิด (NC ต้องเป็นข้อบกพร่องของ[ผู้ปฏิบัติงาน])
4. **Canned-phrase:** Finding ข้อความเดียวกันซ้ำหลายข้อ ไม่อ้างหลักฐานเฉพาะ → ตรวจไม่จริง
5. **Emotional/blaming:** "แย่/หย่อนยาน/ไม่ใส่ใจ" + remark กล่าวโทษคน → ละเมิด Fair presentation & Integrity
6. **One-word verdict:** "ผ่าน/ปกติ/โอเค" โดยไม่มีหลักฐาน → INSUFFICIENT แม้ทิศทางอาจถูก
