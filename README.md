## ความมั่นใจ (Confidence) คืออะไร

**ไม่ใช่** ความมั่นใจของ AI ในคำตอบตัวเอง — LLM ประเมินตัวเองไม่ได้ และมักตอบ 95%
เสมอไม่ว่าจะถูกหรือผิด ที่นี่คือ **คะแนนคุณภาพหลักฐาน** ที่คำนวณจากเอกสารที่ค้นเจอ
ก่อน AI จะเริ่มเขียนคำตอบด้วยซ้ำ

```
confidence = 0.55 × coverage    ครอบคลุมสาระของคำถามกี่ส่วน
           + 0.30 × top1        เอกสารที่ดีที่สุดตรงแค่ไหน
           + 0.15 × agreement   มาจากกี่เอกสารที่ต่างกัน
```

| ช่วง | ความหมาย |
|---|---|
| 80–97% | หลักฐานชัด สอดคล้องกันหลายแหล่ง ใช้ได้เลย |
| 55–79% | ตอบได้ แต่ควรเปิดเอกสารต้นฉบับยืนยันก่อนใช้ |
| ต่ำกว่า 55% | ระบบ **ไม่ตอบ** — บอกตรงๆ ว่าคลังยังไม่มีข้อมูล |

**ทำไมไม่มีวันได้ 100%** — ระบบตั้งเพดานไว้ที่ 97% โดยตั้งใจ เพราะ 100% แปลว่า
"ไม่มีทางผิดเลย" ซึ่งไม่จริงสำหรับระบบที่ค้นเอกสารมาตอบ เอกสารอาจเก่า ขัดแย้งกัน
หรือตีความได้หลายทาง การแสดง 100% จะทำให้คนเลิกตรวจสอบ ซึ่งอันตรายกว่า

**วิธีทำให้คะแนนสูงขึ้นจริง** — เรียงตามผลลัพธ์
1. **เพิ่มเอกสารจริงเข้าคลัง** (ได้ผลมากที่สุด) ตอนนี้บางผู้เชี่ยวชาญมีเอกสารน้อยมาก คะแนนจึงตันที่ 60–70%
2. **ถามให้เจาะจง** — "แบริ่งปั๊มป้อนน้ำ P-201 ร้อน 85°C" ได้คะแนนสูงกว่า "ปั๊มมีปัญหา" มาก
3. **ถามในห้องที่ถูก** — ถามผิดห้องคะแนนตกทันที (ระบบจะเตือนให้)
4. เปิดโหมด Supabase เพื่อใช้ pgvector ค้นเชิงความหมายเพิ่ม

## เชื่อมกับ GitHub

repo ถูกตั้งค่าไว้แล้ว (commit แรกเสร็จ, `.gitignore` กัน PDF 130 MB ที่เกินลิมิต GitHub)
เหลือแค่ผูกกับ repo บน GitHub

**ครั้งแรก — ทำครั้งเดียว**
1. สร้าง repo เปล่าที่ https://github.com/new (อย่าติ๊ก *Add a README*)
2. ผูก remote:
```bash
powershell -ExecutionPolicy Bypass -File scripts\sync-github.ps1 -Remote https://github.com/USER/REPO.git
```
3. ถ้า push แล้วขึ้นว่าล็อกอินไม่ผ่าน ให้เปิด PowerShell ของคุณเองแล้วรัน `git push -u origin main`
   จะมีหน้าเบราว์เซอร์ให้ล็อกอิน GitHub — ทำครั้งเดียว Windows จะจำไว้

**ครั้งต่อไป**
```bash
powershell -ExecutionPolicy Bypass -File scripts\sync-github.ps1 -Message "แก้ไอคอน"
powershell -ExecutionPolicy Bypass -File scripts\sync-github.ps1 -Rebuild   # สร้างคลังใหม่ก่อน push
powershell -ExecutionPolicy Bypass -File scripts\sync-github.ps1 -DryRun    # ดูว่าจะ push อะไร
```

สคริปต์จะ**ตรวจไฟล์เกิน 95 MB ให้ก่อน push** และยกเลิกให้ถ้าเจอ
เพราะ GitHub ปฏิเสธทั้ง commit ถ้ามีไฟล์เกิน 100 MB

> ⚠️ `.gitignore` กัน `.env` และไฟล์ที่มีคำว่า secret/key ไว้แล้ว
> แต่ **อย่าใส่ API key ลงในไฟล์ใดๆ ในโปรเจกต์** — ใส่ผ่านหน้าตั้งค่าของแอปเท่านั้น

## ติดตั้งโหมด Production (Supabase)

### สิ่งที่ต้องมี
| รายการ | จำเป็น | หมายเหตุ |
|---|---|---|
| โปรเจกต์ Supabase | ✅ | ฟรี tier ก็พอสำหรับเริ่มต้น |
| Anthropic API key | ✅ | console.anthropic.com |
| Voyage AI key | ⬜ แนะนำ | dash.voyageai.com (มี free tier) — ถ้าไม่มี ระบบใช้ full-text search แทน |
| Supabase CLI | ⬜ | ใช้ deploy Edge Functions — ติดตั้งผ่าน `scoop install supabase` หรือดาวน์โหลด exe |

### ขั้นที่ 1 — สร้างฐานข้อมูล
เปิด Supabase Dashboard → **SQL Editor** → รันตามลำดับ:
1. `supabase/migrations/001_init.sql`
2. `supabase/migrations/002_modules.sql`
3. `supabase/migrations/003_seed_kb.sql` (ไฟล์ใหญ่ ~540KB — ถ้า editor ไม่รับ ให้แบ่งรันหรือใช้ `supabase db push`)

ตรวจผล: `select * from kb_stats();` ควรเห็น 12 โมดูลพร้อมจำนวน chunks

### ขั้นที่ 2 — Deploy Edge Functions
```bash
supabase login
supabase link --project-ref <PROJECT_REF>
supabase functions deploy ask
supabase functions deploy embed-kb
supabase secrets set ANTHROPIC_API_KEY=sk-ant-api03-xxxx
supabase secrets set VOYAGE_API_KEY=pa-xxxx
```

### ขั้นที่ 3 — สร้าง embeddings (ข้ามได้ถ้าไม่มี Voyage key)
เรียกซ้ำจนกว่า `remaining = 0` (ครั้งละ ~96 chunks):
```bash
curl -X POST "https://<PROJECT_REF>.supabase.co/functions/v1/embed-kb" -H "Authorization: Bearer <ANON_KEY>"
```
เสร็จแล้วรันใน SQL Editor:
```sql
create index idx_chunks_embedding on kb_chunks
  using ivfflat (embedding vector_cosine_ops) with (lists = 100);
```

### ขั้นที่ 4 — ชี้แอปไปที่ Supabase
เปิด `web/index.html` → ⚙ ตั้งค่า → เลือก **Production — ผ่าน Supabase**
→ ใส่ Project URL + anon key → บันทึก

และลองถาม "ราคาหุ้นวันนี้เท่าไร" — ระบบจะปฏิเสธเพราะอยู่นอกคลังความรู้ (พฤติกรรมที่ถูกต้อง)

## หลักการที่ระบบยึด

1. **ไม่โหลดเอกสารทั้งหมด** — ค้นเฉพาะคลังของผู้เชี่ยวชาญห้องนั้น
2. **ตอบจากคลังเท่านั้น** — confidence < 55% ระบบจะบอกว่าไม่มีข้อมูล ไม่เดา
3. **อ้างอิงได้ทุกประโยค** — ทุกข้อเท็จจริงมีเลข [n] โยงถึงเอกสาร/หัวข้อ
4. **Confidence มาจากการคำนวณ** — จาก coverage + ความสอดคล้องของหลักฐาน ไม่ใช่ให้ LLM เดาเลข
